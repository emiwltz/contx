# CONTX macOS identity probe

**Status:** Identity-only prototype passed; permission attribution not tested

**Date:** 2026-08-22

**Authorization owner:** Emi

## Purpose and hard boundary

The second supervised activation proved that the raw Python LaunchAgent and an
interactive CONTX command receive different Screen Recording decisions on the
target Mac. Emi then explicitly authorized a dedicated macOS identity prototype
without activation or collection.

This prototype was allowed to:

- build one disposable private application bundle;
- launch that bundle once through LaunchServices for at most 20 seconds;
- report only its own bundle name, bundle identifier, executable path, and PID;
- inspect the content-free CONTX lifecycle and aggregate database counters
  before and after the run.

It was not allowed to:

- install or load a LaunchAgent;
- enable window titles, screenshots, or background collection;
- import or call Accessibility, CoreGraphics, Quartz, ScreenCaptureKit, or
  workspace-observation APIs;
- request or preflight a macOS privacy permission;
- read application identity, window metadata, titles, pixels, user input, or
  any stored CONTX content;
- keep the generated bundle or evidence after the bounded test.

## Prototype design

`scripts/build_macos_identity_probe.py` embeds a small Swift source and builds a
new bundle only in an existing private directory. The builder refuses relative
paths, existing destinations, non-`.app` destinations, non-macOS hosts, and
parent directories accessible to group or other users. It stages the complete
bundle beside the destination and atomically publishes it only after a
successful compile, manifest write, ad-hoc signature, and strict signature
verification.

The bundle contract is:

```text
display name: CONTX Identity Probe
bundle identifier: io.contx.identity-probe
package type: APPL
application type: LSUIElement
minimum macOS: 14.0
executable: native arm64 Mach-O
signature: ad hoc, identity io.contx.identity-probe
```

The native executable imports only `AppKit` and `Foundation`. A source validator
rejects permission or collection framework tokens before compilation. At run
time it accepts one new evidence-file path and a lifetime from 1 through 30
seconds, writes the file with mode `0600` inside an already-private directory,
and terminates itself at the bound. The evidence schema hard-codes
`permissionsRequested: false`, `collectionStarted: false`, and
`probeKind: identity_only`.

This is deliberately an experimental identity. `io.contx.identity-probe` is
not an accepted production bundle identifier or public compatibility contract.

## Target-Mac execution evidence

The target was macOS 26.5.2 on arm64 with Apple Swift 6.2.1. The first sandboxed
compile could not access the user's Clang module cache and left no destination.
The host compile then exposed one Swift 6.2 visibility error. The delegate
constant was narrowed to private scope, a source regression assertion was
added, and the corrected build passed.

The final private bundle reported:

```text
Format=app bundle with Mach-O thin (arm64)
Identifier=io.contx.identity-probe
Signature=adhoc
Info.plist entries=13
```

`codesign --verify --deep --strict` reported that the bundle was valid on disk
and satisfied its designated requirement. The bundle, manifest, and executable
used local-user-only directory or file modes.

Immediately before launch, the production CONTX runtime reported:

```text
background configuration: disabled
window titles: disabled
screenshots: disabled
collection control: paused
io.contx.collector: manifest=missing unloaded
io.contx.processor: manifest=missing unloaded
background: inactive
raw usage: 0 bytes
observations: 4
events: 0
model attempts: 0
```

The bundle was launched once with a 20-second lifetime. While PID 23989 was
running, LaunchServices reported:

```text
LSDisplayName=CONTX Identity Probe
CFBundleIdentifier=io.contx.identity-probe
LSBundlePath=<private probe directory>/CONTX Identity Probe.app
CFBundleExecutablePath=<bundle>/Contents/MacOS/CONTXIdentityProbe
```

The private evidence file agreed with LaunchServices and contained only the
probe's identity:

```json
{
  "bundleIdentifier": "io.contx.identity-probe",
  "bundleName": "CONTX Identity Probe",
  "collectionStarted": false,
  "permissionsRequested": false,
  "probeKind": "identity_only",
  "processIdentifier": 23989,
  "schemaVersion": 1
}
```

The executable path was also present and pointed to the bundle's own Mach-O; it
is omitted above only to avoid retaining a deleted temporary path as a durable
interface.

After the 20-second bound, LaunchServices returned no active match and process
inspection returned no probe executable. CONTX remained disabled and paused,
both manifests remained missing and unloaded, raw usage remained zero, and the
aggregate database counters remained exactly 4 observations, 0 events, and 0
model attempts. The exact private temporary directory was then deleted, and a
targeted search found no remaining `contx-identity-probe.*` directory.

## Conclusion and next gate

The prototype proves that the target Mac can build, sign, launch, identify,
bound, and clean up a dedicated native CONTX application identity without
touching collection or privacy APIs. It rejects the earlier raw unbundled
Python identity as the only supervision surface.

It does not yet prove:

- that Screen Recording can be granted to this bundle;
- that a Python child launched by this application inherits the intended TCC
  attribution;
- that the application can safely supervise the existing collector;
- that an ad-hoc signature preserves permission identity across rebuilds;
- that a final bundle identifier, signing identity, install location, helper
  boundary, or update strategy has been accepted.

Apple documents that macOS uses a code signature's designated requirement to
recognize code that previously received a privacy permission. Apple also warns
that an ad-hoc signature's designated requirement is tied to that specific
version of the code, so it cannot provide durable authorization across rebuilds.
The next decision must therefore select a prototype signing strategy before any
Screen Recording request. A shared Python permission remains rejected.

No permission request, stable installation, collector integration, LaunchAgent,
background activation, or real-data pilot is authorized by this result.

The later read-only signing inventory and gated permission-attribution
preparation are recorded in
[`v0.1-macos-permission-attribution-preparation.md`](v0.1-macos-permission-attribution-preparation.md).
The request and verification modes were prepared but not executed.
