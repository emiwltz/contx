# v0.2 local model preflight

**Status:** In progress; not a v0.2 completion claim

**Evidence date:** 2026-08-02

## Purpose

This report records the first end-to-end evidence for the mandatory local
multimodal model selected in ADR 0009. It uses synthetic pixels and metadata
only. It does not authorize real screen collection and does not prove the
complete J2 processing, persistence, replay, privacy, or resource gates.

## Selected local runtime

The approved development baseline on the target M4 Mac with 16 GB of memory is:

```text
provider: ollama
endpoint: http://127.0.0.1:11434
runtime version: 0.32.5
model: qwen3-vl:4b-instruct-q4_K_M
model digest: ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b
```

The model occupies approximately 3.3 GB in Ollama's external local store. It
is not a repository artifact and is not downloaded automatically by CONTX.

## Boundary evidence

The implementation currently proves that:

- configuration accepts only an `http` endpoint with an explicit port and a
  literal IPv4 or IPv6 loopback address;
- hostnames, LAN addresses, HTTPS endpoints, credentials, paths, queries, and
  fragments are rejected before transport construction;
- the HTTP transport sends only fixed `/api/*` paths and does not implement
  redirects;
- request and response sizes and timeouts are bounded;
- image bytes and permitted metadata are excluded from request `repr` and
  generic `model_dump` output;
- runtime HTTP bodies and invalid model content are never copied into public
  error messages;
- the provider preflights the runtime version, exact model identity, and model
  digest before interpretation;
- the prompt treats pixels and metadata as untrusted content, separates
  observed facts from inferences, and requests no chain-of-thought;
- Ollama receives a grammar-compatible JSON Schema while the complete Pydantic
  schema independently enforces lengths, ranges, labels, enums, uniqueness,
  and forbidden-sensitivity invariants;
- the accepted execution records the endpoint, runtime, model digest, prompt
  version, output schema version, source identifiers, image hash, latency, and
  token counts without retaining the raw response.

## Real synthetic benchmark

The durable benchmark command is:

```sh
uv run python scripts/benchmark_local_model.py --iterations 1
```

It renders a screen-like PNG in memory through AppKit. It never reads the real
display, window titles, files, clipboard, or user data. The fixture describes a
synthetic CONTX coding task and explicitly identifies itself as test data.

The first successful run produced:

```text
wall duration: 40,689 ms
runtime duration: 40,662 ms
model load duration: 154 ms
prompt evaluation count: 3,937
evaluation count: 217
project: CONTX
sensitivity: public
memory relevance: 0.0
```

The model correctly recovered the project, file, task, four implementation
properties, and synthetic-data notice. It classified the screen as public and
assigned zero memory relevance, which is appropriate for a benchmark fixture.

Repository verification at this checkpoint was:

```text
ruff check: passed
ruff format --check: 134 files already formatted
mypy strict: passed for 73 source files
pytest: 167 passed
git diff --check: passed
```

The first visual attempt exposed an Ollama grammar limitation when the complete
Pydantic schema included regex and length constraints. CONTX now derives a
reduced grammar schema containing only structural types, properties, required
fields, arrays, and enums. The complete strict schema still validates the
returned JSON after generation, so the runtime workaround does not weaken the
application boundary.

## Explicitly not yet proven

J2 remains open because this checkpoint does not yet provide:

1. persisted model transformations and processing-run linkage;
2. a restart-safe queue for collected screenshot observations;
3. idempotent replay across prompt, model, and schema versions;
4. an event builder driven by local-model interpretations;
5. sensitive and excluded synthetic fixture coverage end to end;
6. backlog behavior when Ollama or the configured model is unavailable;
7. repeated warm/cold latency, CPU, peak-memory, and energy measurements;
8. comparison against another model size if the pilot quality is insufficient.

No real user screenshot, title, or persistent background process was activated
for this preflight.
