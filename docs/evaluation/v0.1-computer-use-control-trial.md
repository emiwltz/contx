# Computer Use control trial — 2026-09-12

## Scope

Emi explicitly authorized autonomous Computer Use interactions with open apps,
without concurrent user input. Tests retained the metadata-only scope: private
isolated runtime, no titles/images, no model processing, no LaunchAgents and a
five-minute supervisor bound per session. The installed signed release was not
changed.

On entry, CONTX was active in the earlier test runtime. It was paused via its UI,
then closed. Read-only checks confirmed that titles and captures were disabled
there and that the normal runtime remained disabled. No cause is inferred for
that pre-existing activation.

## Successful controls

Two fresh sessions started paused with zero observations. Computer Use clicked
Resume, then exercised timed or indefinite pause, resumed and clicked the red
close button while the UI and the independent status service reported active
collection.

Both sessions ended because the native host exited, before the supervisor's
five-minute limit. Crucially, the supervisor recorded both host absence and no
collector lease **before** its cleanup ran. Thus cleanup did not supply the
observed collector shutdown. Independent process checks also found no remaining
native host or collector.

The first session's timed pause persisted a deadline exactly 900 seconds after
its pause timestamp. Forty-eight supervisor samples during that pause retained
the same nine-observation count, despite attempted application changes. Resume
worked afterward. The natural fifteen-minute expiry was not tested.

Final totals were eleven and five observations respectively. Every observation
had null window-title and image-artifact fields. The first session explicitly
confirmed zero events and model transformations. Both supervisors confirmed the
normal runtime fingerprint unchanged and the sealed release valid, and returned
their test configurations to disabled. Private raw evidence stays outside Git.

## Application-switch comparison is inconclusive

Selecting and raising Finder/Spotify windows through Computer Use, then clicking
existing controls in those windows, did not yield the expected Finder/Spotify
segments. The first session recorded CONTX and brief other foreground apps; the
second recorded CONTX and system-state segments. A Cmd-Tab attempt did not
establish a usable independent foreground-application reference either.

Accessibility focus/target-window state is insufficient evidence that macOS has
made that app the foreground process sampled by CONTX. These tests therefore
validate the CONTX control actions, not foreground attribution for the targeted
apps. No collector bug or Computer Use root cause is asserted, and the earlier
commentary assuming those app segments was superseded by the database inspection.

Querying the CONTX UI after its verified exit caused an application window to
appear again; it was closed and final absence was checked through processes
without further UI queries. Avoid querying a terminated app as proof of exit.
