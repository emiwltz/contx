The original build checkpoint remained within that boundary. One generated

## Accepted process boundary

ADR 0020 replaces the raw Python collector LaunchAgent with one native AppKit
host:

```text
io.contx.collector LaunchAgent
    -> ~/Applications/CONTX.app/Contents/MacOS/CONTX
        -> digest-pinned contx-native-control
        -> digest-pinned contx-collector
             (CONTX_NATIVE_HOST=1, no Python status item)

io.contx.processor LaunchAgent
    -> contx-processor
```

The native process owns the only menu-bar item and the collector remains the
only process that samples activity, applies exclusions, captures an accepted
focused window, writes raw observations, and owns the daemon lease. The host
does not import or link ScreenCaptureKit, ApplicationServices, Quartz capture,
SQLite, model, memory, or networking APIs.

The existing collector detects the exact `CONTX_NATIVE_HOST=1` marker and then
uses an accessory-only child controller that creates no `NSStatusItem`. Manual
diagnostic collector execution without that marker retains the existing Python
menu; the managed LaunchAgent no longer targets that raw entrypoint.

## Native menu and lifecycle behavior

The AppKit host renders one compact square menu item with six explicit states:

- starting;
- collection disabled;
- collector stopped;
- collection paused;
- collection active;
- collector error.

It exposes only fixed actions: pause for 15 minutes, pause indefinitely, resume,
and restart a stopped collector while paused. It accepts no path, command, shell
fragment, or arbitrary argument from a menu action.

The host loads a signature-sealed, versioned `RuntimeContract.plist`. The
contract contains build-time canonical paths and SHA-256 digests for exactly
the collector and native-control entrypoints. Before every use, the host rejects
a missing, final-component symlinked, changed, non-regular, or non-executable
command. It supplies a minimal environment, starts the collector with no
arguments, stops that child on application termination, and persists a pause if
an owned collector exits unexpectedly.

If a collector lease is already live but was not created by the current host,
the host refuses to start another child. A child that exits before successful
startup is not retained as a running process. Control commands are limited to
five seconds and 32 KiB of output.

## Content-free native control contract

The `contx-native-control` entrypoint returns strict schema-version-1 JSON with
only:

- whether background collection is enabled;
- whether collection is effectively paused;
- whether the exclusive collector lease is live;
- one derived state: `disabled`, `stopped`, `paused`, or `active`.

Pause and resume delegate to the existing `CollectionControlService`. Resume
fails closed while background collection is disabled or the collector lease is
absent. The command reads no observation, title, screenshot, event, model
result, memory, or user-authored content. When configuration is disabled, that
stronger state reports effectively paused without opening SQLite. This avoids
the WAL shared-memory mutation exposed by the first disabled smoke. Enabled
states continue to read the durable pause row.

## First disabled native-host smoke and correction

Emi separately authorized one bounded target-Mac smoke of a fresh signed bundle
with configuration disabled and collection paused. The process ran with the
expected `io.contx.desktop` identity, the content-free control response remained
`disabled`, and no collector, processor, permission request, raw artifact,
LaunchAgent, or collection path started. Emi could not observe the compact menu
item, including after expanding Hidden Bar across the full menu-bar width.
Unified logs showed the native process continuing to send status-item updates
to Control Center without an AppKit error, so the required optical gate failed
despite the live process.

The smoke also invalidated two assumptions in its original protocol:

- macOS registered the running bundle with LaunchServices even though the
  executable was invoked directly and no explicit registration command was
  used;
- repeated read-only SQLite connections updated the modification time of
  `contx.db-shm`, although the database, WAL, configuration, raw store, logs,
  collector state, and processor state otherwise remained unchanged.

Cleanup stopped the process, deleted the exact private bundle, removed its
stale LaunchServices entry, restored both changed Hidden Bar preferences, and
confirmed zero raw artifacts and no repository change. The result is a failed
smoke, not activation evidence.

The repository correction now short-circuits disabled status before SQLite,
defines that state as effectively paused, gives the native status item a stable
autosave name and accessibility identifier, explicitly requests square visible
placement, and terminates if AppKit cannot attach a real button to the system
status bar. Synthetic regression tests prove repeated disabled reads leave all
runtime files byte-for-byte and metadata-identical. Apple's documented
`isVisible` limitation means a new human-observed smoke remains mandatory.

## Corrected registered smoke and text diagnostic

Emi separately authorized a second disabled smoke after the repository
correction. Its initial state had background collection and screenshots
disabled, an effective pause, no collector or processor, no owned LaunchAgent,
no prior `io.contx.desktop` registration, and the accepted 1 GiB temporary raw
budget. The complete runtime-file fingerprint was
`19070f2d206b14e9bd8ed5abc4cd2f26bb9c00b8641066eab0902625660c4aef`.

A fresh arm64 bundle was signed, strictly verified, explicitly registered with
LaunchServices, and launched normally. LaunchServices and the live PID both
resolved to the exact private bundle and `io.contx.desktop`. The content-free
state remained `disabled` and effectively paused, no collector or processor
started, and the runtime fingerprint, file counts, and disk use remained
identical before, during, and after execution. The host remained alive, which
proves that AppKit returned an attached, programmatically visible button under
the fail-closed checks. Emi still observed no CONTX item, so the human optical

Rollback terminated the exact PID, removed the exact LaunchServices entry,
deleted only the inspected private bundle directory, and confirmed no process,
LaunchAgent, registration, runtime mutation, or repository change remained.
The result isolates the remaining defect to visual rendering or menu-bar
placement; it is not activation evidence.

The builder now exposes an explicit, default-off
`--status-item-text-diagnostic` mode. It compiles the same audited host and menu
with a variable-width `CONTX TEST` label instead of the normal symbol and adds
`CONTXStatusItemTextDiagnostic=true` to the signed Info.plist. A normal build
does not receive the compiler flag or diagnostic marker and retains the compact
square symbol. The diagnostic has been implemented and statically tested only;
launching it requires a separate live-test authorization.

## LaunchAgent preactivation behavior

The continuous LaunchAgent manifest now targets only
`~/Applications/CONTX.app/Contents/MacOS/CONTX`; it no longer launches
`contx-collector` directly. The periodic processor remains a separate bounded
job.

Manifest rendering accepts the future absolute application path so read-only
preflight can run before installation. Inspection reports
`io.contx.collector:executable_unavailable` when the app is absent. Both staging
and loading revalidate every program as a regular, non-symlink executable
immediately before mutation. Therefore a missing or replaced app is visible
during preflight and cannot be silently staged or launched.

## Build and signature boundary

The repository builder:

- requires a new absolute `CONTX.app` destination in a private canonical
  directory;
- requires explicit canonical collector and control executables;
- requires an explicit Apple Development identity;
- requires a 40–240 character single-line Screen Recording usage description;
- validates the auditable Swift source before compilation;
- uses only Xcode's Swift compiler and macOS system frameworks;
- writes a binary `Info.plist` with `LSUIElement=true`, the approved product
  identity, and the supplied usage description;
- compiles and signs in a private sibling staging directory;
- enables the hardened runtime and performs strict deep signature verification;
- atomically publishes only a complete verified bundle;
- removes staging state after success or failure;
- requires an explicit build flag for the marked `CONTX TEST` visual
  diagnostic while leaving normal builds unchanged;
- never launches, opens, registers, installs, or activates the application.

No third-party dependency was added. In particular, no Xcode package, native
package manager, telemetry library, updater, or privileged helper was
introduced.

## Remaining gates before activation

This implementation is intentionally not yet launch-ready for real collection.
A separately authorized text diagnostic may precede runtime packaging because
the corrected disabled smoke already proved that no collector child starts:

1. **Text-label diagnostic smoke.** The signed default-off `CONTX TEST` build
   must be separately authorized for temporary LaunchServices registration and
   normal launch under the same disabled, paused, no-child, no-permission,
   no-LaunchAgent, and no-mutation guards. Visibility distinguishes symbol
   rendering from broader status-item placement, but does not activate or
   validate collection. The preparation does not authorize this live action.
2. **Runtime packaging decision.** The development bundle pins commands in the
   repository virtual environment by digest, but does not embed their Python
   interpreter, modules, PyObjC libraries, or OptMem runtime. This detects
   mutation but does not provide a self-contained installed runtime. A packaging
   approach and any material dependency require Emi's approval before any
   collector-child or activation test.
3. **Final permission wording.** Emi must approve the exact French Screen
   Recording explanation that will be embedded in the test bundle before any
   permission request.
4. **Authorized installation build.** A fresh bundle must be built from the
   accepted runtime closure, strictly verified, copied unchanged to
   `~/Applications/CONTX.app`, and registered only under a new explicit
   authorization.
5. **Permission and child attribution.** Screen Recording should be requested
   once with approved wording, then verified from the unchanged app and its
   sealed runtime without reading a title or pixel.
6. **Supervised activation.** Only after the earlier gates pass may a separately
   authorized LaunchAgent activation start the paused native host and collector,
   resume the exact accepted features, and verify real menu, permission,
   lifecycle, exclusion, retention, and zero-unexpected-data behavior.

## Rollback

Before installation, rollback is limited to deleting generated temporary
bundles and reverting repository commits. No system or user runtime state has
been changed by this checkpoint.

After a future installation, rollback must pause collection, unload both owned
LaunchAgents, disable background features, remove only exact owned manifests,
remove the Screen Recording grant, unregister the app, and only then remove the
unchanged installed bundle. Each system-changing phase remains separately
gated.
