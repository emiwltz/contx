# Private runtime feasibility — 2026-09-12

**Outcome:** Isolated feasibility passed; packaging decision proposed, no installed
or activation-ready release produced.

## Observed baseline

- Repository at `d7d5865`, clean before the experiment.
- Python 3.12.13 comes from a shared uv-managed distribution; `.venv/bin/python`
  resolves outside the repository environment.
- Installed CONTX is editable and `contx.pth` points to the working checkout.
- Native signing currently pins only two entrypoint script hashes.
- OptMem executes through an env-python shebang; the native host supplies only
  `/usr/bin:/bin`. Its path and interpreter must be explicit in a packaged release.

## Disposable experiment

1. Copied the current 50.8 MiB base Python distribution to a fresh private
   temporary directory, preserving internal symlinks.
2. Ran the copy in Python isolated mode from outside the repository. Its prefix
   and base prefix resolved inside the temporary copy; SSL and SQLite imported.
3. Recreated an environment against this interpreter using `uv sync --frozen
   --no-dev --no-editable --no-python-downloads --link-mode copy`. The initial
   offline attempt stopped because the locked SQLAlchemy wheel was absent from
   cache. Retried with downloads of already-locked production dependencies;
   no package requirement or lockfile was changed.
4. Installed 29 distributions including CONTX; installed environment size was
   55.3 MiB. Neither Python nor the environment had symlinks outside the private
   experiment root. This checks symlinks, not all Mach-O loader dependencies.
5. From outside the checkout, Python `-I -B` loaded CONTX from the new environment,
   not the repository. AppKit, Quartz, ApplicationServices, SSL and SQLite imports
   succeeded. Packaged `web/static/index.html` was present.
6. Copied only the reviewed OptMem executable into private temporary storage.
   Its normal checksum-validating adapter used a PATH preferring private Python,
   initialized synthetic memory, appended a synthetic line and retrieved it via
   `wake`. An initial probe assertion used the wrong field name (`text` instead
   of `content`); after correcting the probe, the round trip passed.
7. Ran native-control status against a separate nonexistent temporary runtime
   root: disabled, effectively paused, no running collector.

No GUI application, collector, processor, permission request, live observation,
model inference, LaunchAgent or user-data initialization was started. Existing
CONTX source, `.venv`, lockfile and user runtime were not modified by the probe.
Temporary synthetic files and a build cache are not an installed runtime.

## What remains unproven

- Signed full-runtime inventory validation and mutation rejection.
- Native shared-library closure beyond successful imports and symlink checks.
- Launch wiring for private OptMem, control and periodic processor.
- Validation overhead, release update/rollback and read-only permissions.
- Permission attribution and actual child lifecycle under the packaged host.
- Public distribution suitability; OptMem public redistribution remains gated.

## Sources and next decision

Python documents that virtual environments must be recreated at their target
path rather than moved: <https://docs.python.org/3.12/library/venv.html>.
uv documents its use of python-build-standalone distributions:
<https://docs.astral.sh/uv/concepts/python-versions/>.
The experiment verifies only the concrete installed Python snapshot.

Review proposed ADR 0022 before implementing the durable packaging/launch
contract. Isolated imports and memory output do not satisfy the activation gate.
