## Why the fallback was activated

The initial long-history run used a valid explicit correction that included
both the current fact and a clause naming the obsolete claim. The real root
merge returned the equivalent of:

```text
Correction: Atlas deploys to production with Python 3.12 runtime, but its target is edge-only; docs are in English.
```

That wording retained the superseded production target as a current deployment
claim. Strengthening compression prompt `memory-compression-v2` and composing
replacement-only correction lines removed that particular root ambiguity in
the final matrix.

The normal budgeted historical wake nevertheless still exposed two child
summaries at the same time:

```text
#0-15 Correction: Atlas deployment target is production-only; runtime requires Python 3.12; ...
#16-23 Correction: Atlas deployment target is edge-only; Atlas documentation is in English; ...
```

Chronology and the correction protocol make the second line authoritative, but
this remains a historical view that requires every consumer to resolve a
correction chain. The product requires an active-only `wake`, so the fourth
revisit condition in ADR 0013 was met even though the final replacement-only
root summary happened to be correct.

## Publication and recovery proof

The deterministic integration suite covers these boundaries:

1. exact active text is projected and superseded source text is excluded;
2. an unchanged fingerprint reuses the ready generation with no compression;
3. an append failure during a changed build leaves `CURRENT.json` and the
   previous generation intact;
4. a malformed regular pointer is recovered from a complete content-addressed
   generation;
5. a SQLite active-set change during compression discards the stale build and
   retries before publication;
6. a generation-specific continuation token resumes the old retained
   generation after an active change;
7. a symlinked pointer is rejected without reading or overwriting its target;
8. an empty active set produces a complete empty wake.
9. two forced rebuilds of an unchanged source fingerprint publish distinct
   complete generations, reuse the newest one, and retain only the newest two.

The generation protocol uses a private process lock, `.building-*` directory,
readiness marker, a short SQLite immediate writer reservation around the final
fingerprint recheck and publication, atomic same-filesystem rename, atomic
private pointer replacement, and directory `fsync`. Only the current and
immediately previous derived generations are retained. Historical `memory/`
data is outside this cleanup boundary.

## Pagination contract

Upstream OptMem identifies a wake snapshot only by entry count. A correction
can replace one active record with another without changing that count, so the
raw token cannot identify a projection generation.

CONTX now exposes a stable integer derived from the generation fingerprint.
For a continuation, the gateway resolves that token against retained ready
generations and passes the selected generation's internal count to OptMem. If
the generation is no longer retained or the token is ambiguous, wake fails and
asks the caller to restart rather than combining pages from different active
states.

## Correction and compression prompts

`memory-compression-v2` preserves `Correction:` transitively across child and
parent merges, supplies the newest correction explicitly, removes conflicting
claims, and asks the model to retain older non-conflicting durable facts.
CONTX restores the protocol prefix if model output drops it.

New correction composition uses `memory-correction-v2`. It asks the local model
to state only the authorized current replacement and not quote, repeat, negate,
label obsolete, or otherwise restate the original claim. Existing persisted v1
correction builds remain replayable from their audited candidate text.

`contx memory rebuild-active` is the explicit recovery command for a poor
active summary. It builds a distinct generation from the unchanged source
fingerprint and publishes only after the normal completion and concurrency
checks; it does not mutate the historical summary tree.

One direct synthetic call through the final v2 implementation returned:

```text
prompt=memory-correction-v2
digest=ee665637121887cf3befff38abbb1be4ee117c7db867d97a67e29049ecd7e15f
Correction: Atlas deployment target is edge-only.
```

The output contained the authorized current target and did not contain the
original `production-only` target.

## Residual risks and pilot measurements

- The first wake after an active-set change performs a complete local rebuild;
  latency and energy must be measured with real active-set sizes.
- Two complete derived generations plus an in-progress build can temporarily
  exist; disk use must be measured during the pilot.
- Retaining one previous generation covers one intervening change, not an
  indefinitely delayed continuation.
- Exact active text can still be poorly worded. The v2 correction prompt
  narrows this risk but does not turn the projection into a semantic sanitizer.
- The public distribution rights gate for the ignored OptMem snapshot remains
  unresolved.
- This matrix is synthetic and does not authorize the real-data pilot or
  background collection.
