# v0.5 memory correction and OptMem decision validation

**Status:** Correction strategy complete; remaining J5 agent-integration gates
are still in progress

**Evidence date:** 2026-08-02

## Outcome

J5 now has a restart-safe, append-only correction path using upstream OptMem,
the existing SQLite sidecar, and the mandatory local Gemma model. The selected
v0 strategy is recorded in ADR 0013.

The evaluation used a fresh isolated temporary CONTX runtime, the reviewed
upstream OptMem executable, and the locally installed
`gemma4:e4b-it-qat` artifact. It used only the synthetic CONTX fixture. It did
not activate collection, read window titles or screenshots, process real user
content, or contact a remote service.

## Implemented boundary

`contx correct <memory-id> "<replacement>"` now:

1. requires an active, provenance-backed, durable-memory target;
2. sends the original line and explicit user-authorized replacement to the
   loopback-only local model;
3. validates strict structured output and prepends `Correction: ` in CONTX;
4. stages the candidate, pending memory link, inherited provenance, and
   content-free model audit in one SQLite transaction;
5. appends the correction idempotently to OptMem;
6. atomically activates the successor and marks the original superseded.

The model audit retains provider, endpoint, model, model digest, prompt and
schema versions, timestamps, duration, and the SHA-256 of the replacement. It
does not duplicate the replacement text or the private model output.

## Actual upstream OptMem observations

The same two-entry memory was inspected through normal wake, historical
recall, and a forced summarized wake.

With the normal recent-memory budget, upstream OptMem returned both raw entries
in chronological order:

```text
#0 ... Resume CONTX from its current implementation state; sustained project work resumed after a multi-day gap.
#1 ... Correction: Emi works on CONTX continuously without a multi-day pause.
```

`recall CONTX` also returned both lines. This is accepted historical behavior,
not an active-only view. It proves that sidecar status alone cannot silently
filter the direct OptMem context.

After `contx memory maintain` completed one real local-model compression, the
wake line budget was reduced in that disposable runtime to force the rebuilt
summary path. The result was:

```text
#0-1 Emi works on CONTX continuously.
```

The obsolete multi-day-gap claim was absent. The compression prompt explicitly
treats newer `Correction:` entries as authoritative and forbids turning a
contradicted claim into history, a transition, or an invented date.

## Persistence and replay proof

After the successful correction, SQLite contained exactly:

```text
original link:   superseded
correction link: active, supersedes original
correction build: ollama, gemma4:e4b-it-qat, model digest present,
                  prompt memory-correction-v1,
                  schema memory-correction-output-v1
```

Repeating the exact command returned the same correction memory identifier with
`replayed: yes`. The runtime still contained two OptMem log records, two memory
links, one correction candidate, and one correction-build audit. The model was
not called again.

Failure-injection coverage additionally proves the cross-store boundary: if an
interruption occurs after the OptMem append, SQLite retains the original as
active and the successor as pending. Retrying reuses the persisted candidate
and append key, resolves the same OptMem entry, and finalizes the states without
duplication.

## Safety and negative paths

- Missing targets and non-active targets fail before model composition.
- Sensitive memory cannot cross the durable correction boundary.
- A missing local model, unavailable loopback runtime, invalid response
  envelope, malformed JSON, multi-line content, and oversized UTF-8 output all
  fail closed.
- Error messages do not echo model output or replacement content.
- One unique direct successor prevents correction branching. A later change
  targets the active successor and extends a linear chain.
- Agents receive an instruction that `wake` is chronological, corrections are
  authoritative, `recall` and `zoom` are historical, and `correct` requires an
  explicit user instruction.

## Remaining J5 gates

This result completes the correction strategy and OptMem decision experiment;
it does not complete all of J5. The remaining gates are:

- start an isolated real Codex session through `contx wake` and verify that it
  follows the correction contract;
- validate the same instruction block with another shell-capable agent;
- complete the proposal adoption path without allowing direct agent writes;
- run the broader long-history and correction-chain matrix needed before the
  real pilot.

If those evaluations expose correction ambiguity, summary regression, or
context-budget pressure, ADR 0013 defines the active-projection fallback that
must be evaluated before modifying OptMem itself.
