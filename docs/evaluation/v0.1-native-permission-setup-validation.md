# Integrated native permission setup — 2026-09-12

Status: implementation and synthetic validation passed; updated installation and
live attribution verification pending. ADR 0023 was explicitly accepted by Emi.

## Implemented behavior

The window exposes separate Screen Recording and Accessibility request buttons
and an explicit verification button. Startup and ordinary status polling do not
call permission APIs. Requests and verification require disabled collection and
no live collector; they never enable collection or change feature settings.

Native requests occur only following the matching user action. Verification
reports native and collector-child access separately, using the installed private
interpreter and the collection daemon's exact module with a fixed preflight-only
argument. That path does not construct the collection runtime. Unknown daemon
arguments now fail before collection instead of being silently ignored.

The signed runtime is verified before each setup operation. The child inherits
the normal native-collector environment, emits bounded schema-checked Boolean
results and has a timeout. App shutdown cancels the owned bounded command before
waiting for worker completion. An error never reports access as confirmed.

## Evidence

- 509 pytest tests passed, including a full-module synthetic preflight proving
  that the runtime data root is not initialized. One existing third-party
  Starlette/httpx deprecation warning remains.
- Ruff check and format passed; mypy passed for 132 package source files.
- Compiled actual native source with injected synthetic permission APIs and a
  sealed synthetic child passed request, Accessibility request, granted, denied,
  collection-enabled refusal, malformed response, timeout and cancellation cases.
  Tests assert displayed result text and one request despite repeated clicks.
  No real permission API or collection is invoked by these probes.
- Actual native shutdown and all eight runtime-corruption probes still passed.

## Live gate

Build and sign a new final-path release, preserve the previous signed app and
release, and install with all owned processes stopped. Verify the final signature
and inventory, then open disabled. First ask Emi to run verification without a
request. Request each needed permission only by its explicit button and confirm
the macOS application name. Recheck in the same signed installation, relaunching
if macOS requires it. Native and child preflight availability does not establish
successful title access or focused-window capture; those remain later tests.
