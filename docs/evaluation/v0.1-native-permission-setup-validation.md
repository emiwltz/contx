# Integrated native permission setup — 2026-09-12

Status: implementation, synthetic validation and updated disabled installation
passed; native and child granted preflight observed. ADR 0023 was explicitly accepted
by Emi.

## Implemented behavior

The window exposes separate Screen Recording and Accessibility request buttons
and an explicit verification button. Startup and ordinary status polling do not
call permission APIs. Requests and verification require disabled collection and
no live collector; they never enable collection or change feature settings.

Native requests occur only following the matching user action. Verification
reports native and collector-child access separately, using the installed private
interpreter and the collection daemon's exact module with a fixed preflight-only
argument. That path does not construct the collection runtime. Unknown daemon
arguments now fail before collection instead of being silently ignored.

The signed runtime is verified before each setup operation. The child inherits
the normal native-collector environment, emits bounded schema-checked Boolean
results and has a timeout. App shutdown cancels the owned bounded command before
waiting for worker completion. An error never reports access as confirmed.

## First live preflight

Emi's first verification displayed the generic failure message. Independent
checks found disabled state, no collector, unchanged runtime data and a valid
release. A direct private-Python diagnostic returned valid Boolean JSON, but its
permission values belong to that different launching context and are not used
as evidence of production attribution.

An explicit repeat through the unchanged installed application's verification
button succeeded. UI inspection showed native Screen Recording false and
Accessibility false, with both collector-child values also false. Process
observation confirmed the child used the exact private interpreter and daemon
module with `--permission-preflight` under the installed native host.

The original failure cause remains unresolved: the current UI collapses timeout,
child failure and invalid response into one message. No timeout increase or
automatic retry was introduced. This result validates a subsequent preflight,
not a repair of the initial failure or an access grant. Emi was asked to request
Screen Recording explicitly next, with collection still disabled.
