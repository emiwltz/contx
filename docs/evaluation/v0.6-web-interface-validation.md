# v0.6 local web interface validation

**Status:** Complete

**Date:** 2026-08-13

## Scope delivered

- bounded inspection read models for overview, activity, events, corrections,
  patterns, candidates, final memory, local-model transformations, raw
  artifacts, processing runs, proposals, validations, and settings;
- FastAPI `/api/v1` contract with explicit Pydantic responses;
- literal-loopback `contx web` launch path with no configurable bind address;
- same-origin React/Vite/TypeScript SPA with dashboard, activity, patterns,
  memory, privacy, agent, and settings spaces;
- pause/resume state derived from both the durable pause control and the live
  daemon state;
- exclusion creation, enabling, disabling, and deletion through the durable
  collection-control service;
- direct active OptMem wake preview;
- append-only event and memory correction actions;
- explicit proposal adoption and rejection;
- immediate raw purge with exact confirmation and a distinct audited pipeline;
- full-data deletion with exact confirmation, live-daemon refusal, narrow-root
  checks, SQLite disposal, and API retirement;
- no raw artifact path or raw content endpoint.

The complete suite proves, among other J6 contracts:

- unavailable required-model status is visible and has no semantic fallback;
- persisted pause/resume uses the same application service as the collector;
- untrusted hosts, cross-origin mutations, and non-JSON writes are rejected;

- raw purge and full deletion require their exact, distinct phrases;
- full deletion preserves adjacent unrelated files and refuses unsafe roots or
  a live collector;
- correction and proposal actions reuse the tested append-only application
  services.

## Live loopback and browser evidence

A production build was served from an isolated runtime with:

```text
CONTX_RUNTIME_ROOT=<private-temporary-root> contx web --port 18711
```

`lsof` reported one listener at `127.0.0.1:18711` and no wildcard or external
interface. Requests to `/` and `/api/v1/status` returned 200 with the expected
headers. A hostile `Host` value returned 400.

The in-app browser then exercised the production server, not the Vite
development server:

- all seven navigation spaces rendered an intelligible empty or live state;
- the active OptMem wake preview completed;
- one synthetic exclusion was created, disabled, and deleted;
- full deletion was tested only against the isolated temporary runtime: an
  incorrect phrase kept the action disabled, the exact phrase retired the API,
  and the UI displayed the terminal deleted state;
- semantic snapshots exposed named navigation, headings, regions, fields, and
  destructive controls;
- desktop and 390-by-844 responsive layouts were visually inspected;
- browser console collection returned no warning or error.

Visual QA initially found a material state defect: the overview called
collection “Active” whenever the durable pause bit was false, even when
background collection was disabled and no daemon existed. The UI now exposes
four truthful states: active, paused, stopped, and disabled. Pause/resume is
available only while a collector daemon is actually running. The rebuilt UI
was reloaded and rechecked in both desktop and mobile layouts.

## Residual risk

FastAPI's current test-client compatibility import emits one
`StarletteDeprecationWarning`: Starlette plans to replace the `httpx`-backed
test client with `httpx2`. This affects development tests only, not the served
application. It should be migrated when FastAPI exposes the new client without
adding a speculative second HTTP stack now.

No real collection, system permission request, real-data deletion, LaunchAgent
installation, or pilot activation was performed for J6. Those remain separate
J1/J7 action-time gates.
