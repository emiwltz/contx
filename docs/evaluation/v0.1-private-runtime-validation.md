# Private runtime implementation validation — 2026-09-12

**Status:** Private release and signed native dispatch verified in isolation.
No installed release or real collection.

## Implementation

Accepted ADR 0022 is implemented in the private runtime builder, version-2
signed inventory, native verifier, explicit private Python/OptMem execution and
signed processor dispatch. Version construction never selects or overwrites an
installed app. The obsolete entrypoint-only contract was removed.

The final temporary release is built from production commit `c21695b`. It
contains Python 3.12.13, 28 locked third-party distributions, CONTX as a wheel,
packaged web assets and the reviewed OptMem snapshot. It is read-only, has no
external symlink and retains its final version-specific absolute path.
Generated binaries, manifests and synthetic data are not committed.

## Automated evidence

- 496 pytest tests passed; one existing Starlette/httpx deprecation warning.
- Ruff check and format passed; mypy passed for 130 package source files.
- Builder failure tests preserve prior versions and remove only unpublished
  generated state; manifest publication refuses existing destinations.
- Python tests reject altered interpreter, module, native library and OptMem,
  extra/missing nodes, writable files and external links.
- Compiled Swift probes pass eight mutation cases, including preserved mtime,
  startup corruption and refusal after disk repair. The same tests exercise the
  real host's stop-on-integrity-failure path with disposable `/bin/sleep` children.
- A regression test proves the module-based control command runs once without
  Python's duplicate-import warning and does not initialize disabled state.
- OptMem regression tests prove the current isolated interpreter is used even
  when PATH contains no Python, rather than relying on its env-python shebang.

## Complete private release evidence

- Clean-source build, hash-locked dependency installation and wheel construction
  succeeded twice in distinct version directories; previous versions were retained.
- Approximately 106 MiB of regular runtime files, excluding the model and native app.
- Native load-command audit passed for 181 Mach-O files. All non-system loads
  resolve within the private release. The original absolute LC_ID_DYLIB identifier
  is not a dependency; LC_LOAD commands and actual loaded images were checked.
- Isolated imports of CONTX, AppKit, Quartz, ApplicationServices, SSL and SQLite
  passed. CONTX imports resolve to the private wheel, not the editable checkout.
- Inspection of 837 actual loaded images found no non-system image outside the
  private release for that import scenario. This is not exhaustive execution of
  every optional standard-library feature.
- Synthetic OptMem initialize/append/wake passed with PATH containing no Python.
- Private native-control status returned disabled, effectively paused and no
  collector, using only a temporary runtime root.
- The full release inventory remained unchanged after those probes.

## Verification cost

On the first complete release, full native verification took approximately
0.34–0.76 seconds across measured runs. The initial polling implementation took
84 ms per tick; checking all cached inode/device/size/mode/mtime/ctime stamps,
including directories, reduced this to approximately 9–11 ms per tick while
retaining all mutation refusals. These are elapsed-time probe measurements,
not CPU/power measurements or controlled-day resource acceptance.

## Signing checkpoint

The first signing attempt reached the existing 120-second Keychain timeout.
The builder removed its exact staging application without publishing a partial
app or changing the sealed release. After Emi authorized codesign, the retry
succeeded and the final application passed strict signature verification.

The signed native `--process-once` entrypoint accepted its runtime and reached
the private processor, which exited with the expected background-disabled error
using a synthetic runtime root. A copied application with a modified embedded
manifest was rejected by the native host before initializing its separate
synthetic root. The original signature and full runtime inventory remained valid.
Temporary probe data and the corrupted copy were removed. The valid app and
versioned releases remain temporary build artifacts, not installed applications.

## Remaining live gates

- Prepare and authorize the final installation path and exact permission wording.
  Rebuild at the final version path; the temporary absolute-path release cannot
  be relocated. Then test
  unchanged native host/child permission attribution.
- Validate real collector lifecycle, resource use and exclusion behavior before
  the short supervised session. No test here captures live titles or pixels.

Read-only permissions and polling are protection against accidental mutation,
not a boundary against a hostile account owner/administrator or arbitrary
mutation races. A periodic processor verifies before exec and assumes its
read-only release stays unchanged for that bounded run. Installed release
switching must occur with owned processes stopped.
