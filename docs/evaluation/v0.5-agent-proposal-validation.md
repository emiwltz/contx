## Contract under test

The agent-facing `contx propose` command must not write final memory. An
explicit user-selected `contx proposals adopt <uuid>` operation must:

1. revalidate the current event, pattern, or memory reference and sensitivity;
2. invoke only the configured loopback local model;
3. decide support, ambiguity, duplication, and conflict through strict JSON;
4. append the reviewed proposal unchanged only for `supported_novel`;
5. preserve transitive pattern, event, and observation provenance;
6. audit model identity, protocol versions, confidence, timing, and content-free
   input fingerprints;
7. resume after interruption without another model call or OptMem duplicate.

Model rejection, model deferral, and explicit user rejection must produce no
final-memory write.

## Real local-model findings and iteration

The first combined prompt accepted a supported novel proposal, but also
accepted an exact duplicate and a semantic paraphrase. CONTX added a narrow
exact normalized equality postcondition after the model call. Separating
semantic equivalence into a focused second structured classification fixed the
paraphrase case with the installed Gemma model.

The first unsupported fixture was rejected but mislabeled as an active-memory
conflict even though no active-memory line was supplied. The final protocol
clarifies that active-memory reasons apply only to supplied memory and gives
unsupported reference evidence precedence in the application invariant. The
same fixture then returned the correct audited reason.

These failures were not hidden: they directly changed prompt version
`agent-proposal-adoption-v2`, output-schema version
`agent-proposal-adoption-output-v2`, and the regression tests.

## Disposable end-to-end model proof

The reusable validator creates a temporary migrated SQLite database, persists
one synthetic event and observation, submits three primary-agent proposals,
runs the real local model, uses the in-process idempotent `MemoryStore`, verifies
the final states, and removes the database automatically:

```text
UV_CACHE_DIR=/private/tmp/contx-uv-cache \
uv run python scripts/validate_agent_proposal_adoption.py
```

Observed result:

| Fixture | Proposal state | Decision | Reason | Confidence |
|---|---|---|---|---:|
| Supported novel fact | adopted | accepted | supported_novel | 0.98 |
| Equivalent paraphrase | rejected | rejected | duplicate_active_memory | 1.00 |
| Claim contradicted by reference | rejected | rejected | unsupported_by_reference | 0.98 |

Exactly one of the three proposal lines reached final memory. The semantic
paraphrase and unsupported claim produced audited decisions and zero memory
writes.

## Remaining limits

- The real-model matrix contains three deliberately small English synthetic
  cases. It proves the protocol and catches the observed failure modes, not
  broad semantic quality across languages and domains.
- The end-to-end validator uses `RecordingMemoryStore`; actual long-history
  OptMem correction, compression, wake, recall, and zoom behavior remains a
  separate J5 matrix.
- Semantic duplicate comparison sees at most 32 selected active lines and 8
  KiB. Long-history selection quality still needs stress fixtures and pilot
  measurement.
- Model behavior is bounded with temperature zero, seed zero, strict schemas,
  versioned prompts, and a recorded digest, but future model digests require
  rerunning this matrix.
- No real collection, private user content, or background process was used.
